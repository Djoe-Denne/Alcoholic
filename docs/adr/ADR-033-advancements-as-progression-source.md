# ADR-033: Advancements as Progression Source of Truth

- Status: Accepted
- Date: 2026-08-28
- Extends: [ADR-001](ADR-001-loader-independent-architecture.md)

## Context

Alcoholic needs a guided path (discovery, harvest, must, fermentation,
aging or blending, bottling) that works when the mod is installed
alone. FTB Quests can present the same path in a controlled modpack,
but 1.19.2 FTB Quests pulls Architectury, FTB Library, FTB Teams, and
Item Filters, and loads quests from `config/ftbquests/quests`, not
from the mod JAR.

## Decision

Vanilla advancements are the only progression source shipped in the
Alcoholic core JAR.

- Discovery uses `minecraft:inventory_changed`.
- Harvest and process milestones use two vanilla criterion triggers
  defined in `minecraft-common`: `alcoholic:crop_harvested` and
  `alcoholic:process_completed`.
- Artisanal machines remember the last interacting player. When a
  process completes while that player is offline, the criterion is
  queued on the block and flushed on the next use of that block.
- FTB Quests is not a compile or runtime dependency. A later optional
  chapter should watch these advancement IDs with `AdvancementTask`.
- JSON is generated by extending the Forge-patched 1.19.2
  `AdvancementProvider` (`registerAdvancements`). Forge 43.5 has no
  `ForgeAdvancementProvider` class.

Stable advancement IDs:

- `alcoholic:root`
- `alcoholic:harvest_grapes`
- `alcoholic:harvest_hops`
- `alcoholic:produce_must`
- `alcoholic:ferment_beverage`
- `alcoholic:age_wine`
- `alcoholic:blend`
- `alcoholic:bottle`

Stable trigger IDs:

- `alcoholic:crop_harvested`
- `alcoholic:process_completed`

## Consequences

- A player without FTB still sees the Alcoholic advancement tab.
- Detection is written once. A future FTB chapter does not reimplement
  harvest, fermentation, or bottling checks.
- Industrial multiblocks and Create pipes are out of this delivery; they
  can fire the same triggers later without changing IDs.
